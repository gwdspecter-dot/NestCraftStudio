# NestCraft Studio

**NestCraft Studio** — настольная САПР для проектирования корпусной мебели. Модель собирается из панелей (ЛДСП, МДФ, ХДФ и т. д.) с кромкой, присадкой и крепежом; геометрия строится в твёрдотельном ядре OpenCASCADE (через `build123d`), а показывается в собственном OpenGL-вьюпорте.

Текущая версия приложения — **0.0.19**, формат файла проекта — **0.0.8**. Проект находится в активной разработке: часть возможностей ещё не реализована (см. [«Что пока не сделано»](#что-пока-не-сделано)).

## Возможности

### Панели и модули

- **Панель** — базовая деталь: габариты, положение, материал, кромка на четырёх торцах, пазы и отверстия. Поддерживаются углы поворота `rx`, `ry`, `rz`; поворот применяется вокруг центра детали.
- **Параметрический корпус** (`ParametricCabinet`) строится из ширины, высоты, глубины, толщины, числа полок, наличия фасада и других параметров. При смене параметров панели корпуса не пересоздаются целиком: пересчитываются размеры существующих деталей, а присадка, кромка и материалы сохраняются. Отверстия, поставленные вручную, смещаются вместе с краями детали.
- Корпуса можно создавать из шаблонов в обозревателе библиотеки, а панели — диалогом «Создать панель».
- Каждая панель и блок имеют стабильный `uid`; на него опираются стыки, история изменений и копирование.
- Ввод проверяется: габариты корпуса и деталей ограничены разумными пределами (`core/validation.py`), недопустимые значения отклоняются с понятным сообщением.

### Кромка и пильные размеры

- Кромка назначается на каждый из четырёх торцев панели; толщина берётся из каталога.
- Пильные размеры считаются автоматически и показываются в панели свойств:

  ```text
  L_пил = L − T_лево − T_право
  W_пил = W − T_верх − T_низ
  ```

### Каталог (SQLite)

- Листовые материалы, кромочные ленты, крепёж со схемами сверления, поставщики и категории.
- Браузер каталога (`Ctrl+Shift+M`): поиск, фильтры, создание, редактирование и удаление позиций, назначение материала или кромки выделенной детали.
- Рабочая база лежит в каталоге данных пользователя, а не рядом с программой; при первом запуске в неё копируется встроенный шаблон из `data/catalog/`.

### Стыки и присадка

- **Поиск стыков**: программа находит зону контакта двух панелей (включая повёрнутые) и считает оси сверления.
- **Параметрические стыки** (`JointRecord`): стык хранится как данные (две панели, пресет, параметры), а присадка создаётся из него. При изменении размеров, `rebuild()` корпуса, загрузке файла и в истории изменений присадка пересчитывается; отверстия стыка помечены его `uid`, поэтому ручные отверстия не смешиваются с отверстиями стыка.
- **Пресеты расстановки** (`Tab` / `Shift+Tab`): конфирмат, шкант, эксцентриковая стяжка, полкодержатели. Число точек выбирается клавишами `2`/`3`/`4` или колесом мыши (от 2 до 6).
- **Конструктор фурнитуры** (`Ctrl+H`): сейчас полностью реализован тип «Конфирмат» с параметрами D1 (сверление в пласть), D2 (сверление в торец), H (длина) и H1 (явная глубина). Параметры доходят до сверления, сохраняются в проекте и в списке пользовательских вариантов.
- **Защита от пазов**: отверстие, попавшее в паз задней стенки, сдвигается так, чтобы обе парные детали остались соосными.
- **Сломанный стык**: если панели перестали касаться, присадка снимается, а в окне «Проблемы» появляется замечание `joint_broken`. Вернули деталь на место — присадка возвращается.

### Проверки («Проблемы»)

Окно проблем собирает замечания по сцене: материал или кромка не найдены в каталоге, несовместимая толщина крепежа, разорванные стыки, пересечения деталей и др. Двойной клик по замечанию выделяет деталь. Проверка пересечений выполняется в фоне.

### Вьюпорт

- Режимы: заливка, каркас, X-Ray (скрытые рёбра серым).
- Проекции: изометрия и четыре ортогональных вида.
- **Сечение** (`Alt+S`): плоскость сечения, сдвигаемая `Alt` + колесо.
- **Призраки окружения** (`I`): остальные детали приглушаются, чтобы изолировать выделенную.
- **Линейка** (`M`): привязка к вершинам, рёбрам и граням, замеры расстояний и отступов отверстий.
- **Перемещение** (`G`): блокировка по осям `X`/`Y`/`Z`, `Shift` снимает блокировку; сдвиг стрелками с настраиваемым шагом.
- Масштабирование деталей за угловые маркеры; выделение рамкой в ортогональных видах.
- Светлая и тёмная тема следуют системной.

### Проект

- Многоуровневая отмена и повтор (`Ctrl+Z`, `Ctrl+Y`); история отображается в отдельной панели. Звёздочка «изменено» в заголовке корректно снимается при возврате к сохранённому состоянию.
- Копирование и вставка с точкой привязки (`Ctrl+C`, `Ctrl+V`): у копии новые `uid`, стыки ссылаются на копию.
- Атомарное сохранение (запись во временный файл и замена), список недавних файлов, предупреждение при закрытии с несохранёнными изменениями.
- Автосохранение раз в 60 секунд и предложение восстановить данные после сбоя.
- Окно «Что нового» читает `CHANGELOG.md`.

## Установка и запуск

### Требования

| Компонент | Версия |
|---|---|
| Python | 3.11 или новее |
| PyQt6 | 6.6.0 или новее |
| PyOpenGL | 3.1.7 или новее |
| numpy | 1.24.0 или новее |
| build123d | 0.9.0 или новее |
| Видеокарта | OpenGL 3.3 Core Profile (используется MSAA ×4) |

### Установка

Windows (PowerShell):

```powershell
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Linux / macOS:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python main.py
```

Установка `build123d` подтягивает OpenCASCADE и может занять несколько минут. Если запуск сообщает о нехватке или устаревшей версии `build123d`, установите нужную версию командой из сообщения.

## Данные пользователя

Всё, что создаёт программа, хранится в каталоге данных пользователя (`QStandardPaths.AppDataLocation`, путь содержит `NestCraft`), а не в папке установки:

| Что | Где внутри каталога |
|---|---|
| Журнал работы | `logs/nestcraft.log` (с ротацией) |
| Каталог материалов и фурнитуры | `catalog/nestcraft_catalog.db` |
| Варианты конструктора фурнитуры | `fastener_constructor_rows.json` |
| Файл восстановления автосохранения | рядом с остальными данными, по одному на процесс |

Встроенный шаблон каталога лежит в `data/catalog/nestcraft_catalog.db` и используется только как источник для копирования при первом запуске. При ошибках приложения подробности ищите в журнале.

## Формат проекта `.b3d`

Файл проекта — JSON, версия формата **0.0.8**. Что в нём хранится:

- блоки и панели с `uid`, ролью, размерами, положением, углами, материалом, кромкой, пазами и отверстиями;
- отверстия стыков с меткой `joint_uid` (седьмой элемент кортежа отверстия);
- записи параметрических стыков (`JointRecord`) с пресетом и параметрами конструктора.

Более старые файлы (с версии 0.0.1) открываются через цепочку миграций, например `0.0.7 → 0.0.8`. Файл более новой версии открывается с предупреждением. Если в файле встречаются материал или кромка, которых нет в каталоге, программа сообщает об этом и сохраняет исходную ссылку, а не молча подставляет материал по умолчанию.

## Разработка

### Окружение

```bash
pip install -r requirements-dev.txt
pre-commit install
```

### Тесты

```bash
pytest -m "not slow and not gui"   # быстрые тесты; build123d и OpenGL подменяются заглушками
pytest -m slow                     # тесты на настоящем build123d (нужен установленный build123d)
pytest                             # всё сразу
```

Быстрые тесты работают без GUI и без настоящего OpenCASCADE: заглушки собраны в `tests/conftest.py`. Тесты с маркером `slow` проверяют объёмы отверстий, габарит повёрнутой панели, булевы операции и пересечения на настоящем B-Rep. Маркер `gui` предназначен для тестов Qt (запускаются с `QT_QPA_PLATFORM=offscreen`).

### Качество кода

```bash
ruff check core models ui tests
mypy core models
```

Правила `ruff`: ошибки стиля и импортов (`E`, `F`), запрет глухого `except ...: pass` (`S110`) и слепого `except Exception` (`BLE001`, включено для `models/` и `core/joint.py`, в точках интеграции с OpenGL, Qt, SQLite и build123d отключено осознанно). `mypy` запускается в CI без блокировки сборки.

### CI

Workflow `.github/workflows/tests.yml` содержит две задачи:

- `test`: `ruff`, `mypy` (не блокирует), быстрые тесты;
- `slow`: тесты `-m slow` на матрице версий `build123d` (`0.9.0` и последняя), включая проверку, что в минимальной версии есть `Extrinsic`/`Rotation`.

### Сборка исходного архива

```bash
bash scripts/pack_src.sh [путь/к/архиву.zip]
```

Скрипт исключает `__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache` и служебные каталоги.

### Как добавлять изменения

1. Версию меняйте только в `core/version.py` (`APP_VERSION`, `FORMAT_VERSION`); `pyproject.toml` и `CHANGELOG.md` обновляйте вручную.
2. При изменении формата файла увеличьте `FORMAT_VERSION` и добавьте шаг миграции в `core/project_io.py` вместе с тестом.
3. Каждая запись в `CHANGELOG.md` должна соответствовать коду: окно «Что нового» показывает её пользователям.
4. Для нового поведения добавляйте тест; для логики, зависящей от настоящего B-Rep, — тест с маркером `slow`.

## Что пока не сделано

- Конструктор фурнитуры: кроме «Конфирмата» остальные типы (минификс, шкант, полкодержатель и др.) пока недоступны; кнопки типов есть в интерфейсе.
- Спецификация деталей и расчёт стоимости.
- Карта раскроя листов.
- Экспорт: STEP, DXF и файлы присадки для станков.
- Учёт направления текстуры (`grain_direction` есть в каталоге, но нигде не используется).
- Новые параметрические модули: ящик, дверь с петлями, цоколь, задняя стенка.
