# AGENTS.md — правила работы ИИ-агентов с кодом NestCraft Studio

Этот файл читают ИИ-агенты (Claude Code, Cursor, Copilot, Codex и др.) перед любой правкой. Для людей общее описание проекта лежит в `README.md`. При конфликте этого файла с вашими догадками прав этот файл; при конфликте с кодом — сообщите о расхождении, не подгоняйте молча ни то, ни другое.

Язык: комментарии, docstring, сообщения пользователю, `CHANGELOG.md` и коммиты — **по-русски**, как в остальном проекте. Идентификаторы — по-английски.

---

## 1. Что это за проект

Параметрическая САПР корпусной мебели: Python 3.11+, PyQt6, PyOpenGL (OpenGL 3.3 Core), numpy, build123d (OpenCASCADE). Точка входа — `main.py`. Версия приложения и формата файла — в `core/version.py`.

Слои (зависимости идут только сверху вниз):

```text
ui/            виджеты, вьюпорт, диалоги       ← может импортировать core и models
core/          логика, ядро CAD, ввод-вывод    ← не импортирует ui
models/        Panel, Block, ParametricCabinet ← не импортирует ui
```

- Не добавляйте в `core/` и `models/` импорты из `ui/`. Если логике нужен UI, передайте колбэк или сигнал.
- Не добавляйте зависимости в `requirements.txt` без явной просьбы. Тяжёлый или необязательный импорт делайте ленивым (внутри функции).
- Не переименовывайте и не перемещайте файлы и публичные функции «заодно». Рефакторинг — отдельная задача.

## 2. Обязательный порядок работы

1. **Прочитайте код вокруг места правки**, включая тесты, которые его покрывают (`tests/`). Не опирайтесь на память о том, «как обычно устроено».
2. **Воспроизведите проблему** тестом или коротким скриптом до исправления. Если воспроизвести нельзя, скажите об этом.
3. **Сделайте минимальную правку.** Не трогайте соседний код, форматирование и имена без необходимости.
4. **Добавьте или обновите тест**, который падал бы без вашей правки.
5. **Запустите проверки** (раздел 3) и приведите результат дословно.
6. **Обновите `CHANGELOG.md`**, если меняется поведение для пользователя (раздел 7).
7. **Отчитайтесь честно** (раздел 8): что сделано, что проверено запуском, что только прочитано.

Если задача неоднозначна и неверное допущение дорого обойдётся (формат файла, миграция, публичное поведение), задайте один конкретный вопрос до начала работы. В остальных случаях примите разумное допущение и назовите его в отчёте.

## 3. Команды проверки

```bash
pytest -m "not slow and not gui"     # быстрые тесты, обязательны перед сдачей
pytest -m slow                       # настоящий build123d; запускайте, если трогали cad_kernel, геометрию, сверление, повороты
ruff check core models ui tests      # должен проходить без ошибок
mypy core models                     # в CI не блокирует, но не ухудшайте результат
```

- Тесты запускаются с `QT_QPA_PLATFORM=offscreen`, когда нужен Qt.
- Если окружение агента не позволяет что-то запустить (нет PyQt6, build123d, OpenGL, нет Windows), **так и скажите**. Не пишите «проверено», если вы только прочитали код.
- Падающий тест нельзя править так, чтобы он стал проходить, не поняв причину. Сначала выясните, ошибка в коде или в тесте, и объясните вывод.
- Не используйте `skip`, `xfail`, ослабление допусков и удаление проверок, чтобы «позеленить» набор.

## 4. Инварианты, которые нельзя ломать

Это места, где в проекте уже находили и исправляли ошибки. Любая правка рядом требует теста.

### 4.1. Идентификаторы и стыки
- У каждой панели и блока есть стабильный `uid`. Не генерируйте его заново при `rebuild`, слиянии, загрузке и отмене. При копировании и вставке **у копии новые `uid`**, а ссылки стыков перенацеливаются на копию (`core/clipboard.py`).
- Отверстия стыка помечаются `joint_uid` (7-й элемент кортежа отверстия). Ручные отверстия метки не имеют. Не смешивайте их: пересчёт стыка снимает и ставит только свои отверстия.
- Стык — данные (`JointRecord`), присадка — производная от него. После изменения размеров, `rebuild()`, загрузки, Undo/Redo присадка пересчитывается из записи. Если панели перестали касаться, присадка снимается, создаётся замечание `joint_broken`; при возврате детали присадка возвращается.

### 4.2. Пересборка корпуса и ручные правки
- `ParametricCabinet.rebuild()` и слияние модулей **не должны терять** присадку, кромку, материал, поворот и стыки существующих панелей.
- Отверстия, поставленные вручную, переезжают вместе с краями детали при изменении габаритов. Не сбрасывайте их и не дублируйте.
- Сохраняйте `thickness_axis` и поворот (`rx`, `ry`, `rz`, вокруг центра детали) при сохранении, клонировании и пересборке.

### 4.3. Геометрия и B-Rep
- Сверление в слепое отверстие не должно проходить насквозь: проверяйте объёмом (`test_blind_hole_volume`).
- Порядок поворотов в build123d (`Extrinsic.XYZ`) подтверждён на 0.9.0; не меняйте его без `pytest -m slow`.
- Если B-Rep вернул ошибку или пустую форму, **не оставляйте старую сетку молча**: пишите в лог и показывайте замечание или статус пользователю. Отверстие, которое выглядит на экране существующим, но исчезло из модели, — ошибка.
- Пильные размеры (`L − T_лево − T_право`, `W − T_верх − T_низ`) считаются в одном месте; не дублируйте формулу.

### 4.4. Undo и «изменено»
- Любое изменение модели проходит через команду стека отмены. Состояние «чистый» сравнивается с точкой сохранения, а не сбрасывается при любой команде.
- Команда, которая уже применила изменение «вживую» (например, перетаскивание), кладётся в стек с `execute=False`.

### 4.5. Файлы проекта
- Изменили структуру данных, которые пишет `project_io.py`? Тогда: увеличьте `FORMAT_VERSION`, добавьте шаг миграции `N → N+1`, тест миграции на файле старой версии и круговой тест save → load.
- Старые файлы обязаны открываться. Файл новее приложения открывается с предупреждением, а не падением.
- Сохранение атомарное (временный файл и замена). Не пишите в целевой файл напрямую.
- Недостающий материал или кромка каталога не подменяются молча материалом по умолчанию.

### 4.6. OpenGL и Qt
- Ресурсы OpenGL (VAO, VBO, текстуры, шейдеры) создаются и освобождаются **только при активном контексте** (`makeCurrent()` / `doneCurrent()`).
- Код вьюпорта не может быть проверен без GL-контекста. Любую правку шейдеров, отсечения (`GL_CLIP_DISTANCE0`), прозрачности, освещения помечайте в отчёте как **непроверенную запуском** и просите проверку на реальной видеокарте (Intel и AMD, OpenGL 3.3 Core).
- Фоновые задачи не трогают виджеты и GL напрямую; результаты возвращаются сигналами в главный поток.
- Один шорткат — одно `QAction`. Не создавайте второй `QAction` с тем же сочетанием клавиш (неоднозначные шорткаты в Qt не срабатывают); для кнопки и пункта меню используйте общий объект.

### 4.7. Windows и процессы
- Вызовы WinAPI через `ctypes` всегда с явными `argtypes` и `restype`.
- Для автосохранения и определения «чужого» процесса сравнивается PID и время старта процесса. Не опирайтесь на «текущее время» как на время старта чужого процесса.

## 5. Стиль кода

- Тип-подсказки в новом и изменённом коде обязательны для публичных функций.
- **Запрещено `except Exception: pass` и голый `except:`.** Ловите конкретное исключение; если ловите широко (границы Qt, OpenGL, SQLite, build123d), логируйте через `logging` с `exc_info` и объясните причину комментарием. Тесты `test_no_silent_except_*` проверяют это.
- Без `print()` в рабочем коде — используйте `logging.getLogger(__name__)`.
- В рабочем коде не должно быть заглушек и тестовых классов (вроде `_Dummy`). Заглушки Qt и build123d живут только в `tests/` и `core/_qt_compat.py`.
- Не оставляйте неиспользуемые импорты и переменные: `ruff` и `test_code_quality_*` их ловят.
- Числа с физическим смыслом (мм, градусы) называйте и документируйте единицы. Углы в API — градусы, если не сказано иное.
- Комментарий объясняет «почему», а не повторяет код.
- Не вводите магические числа в геометрии: допуск и константы — именованные, рядом с использованием.

## 6. Тесты

- Новый тест кладите в `tests/test_<тема>.py`. Не раздувайте существующие файлы несвязанными проверками.
- Тесты не должны зависеть от жёстко записанной версии приложения. Версию берите из `core/version.py`, а не пишите литерал `'0.0.18'` в проверках.
- Тест, которому нужен настоящий build123d, помечайте `@pytest.mark.slow`; которому нужен Qt — `@pytest.mark.gui`.
- Проверяйте поведение, а не реализацию: объём после сверления, координаты, число отверстий, содержимое сохранённого файла после загрузки.
- Для исправления ошибки: сначала тест, который падает, потом правка, потом тот же тест проходит.
- Не удаляйте и не ослабляйте существующие тесты без объяснения в отчёте.

## 7. Версии, `CHANGELOG.md`, документы

- Версию меняйте только если вас об этом попросили. Тогда одновременно: `core/version.py`, `pyproject.toml`, заголовок в `CHANGELOG.md`, `README.md`.
- Запись в `CHANGELOG.md` описывает только то, что реально работает и проверено. Не пишите абсолютных обещаний («всегда», «никогда», «гарантированно»), если нет теста или расчёта, который это подтверждает. Окно «Что нового» показывает текст пользователям.
- Если вы добавили горячую клавишу, пункт меню или параметр, обновите таблицу управления в `README.md`.
- Не создавайте новые отчёты, планы и заметки в репозитории без просьбы.

## 8. Как отчитываться

Ответ после выполнения задачи содержит:

1. **Что изменено** — файлы и суть, коротко.
2. **Что проверено запуском** — команды и результат (`N passed, M failed`). Только то, что вы действительно запускали.
3. **Что проверено только чтением кода** и что не проверено вовсе (GL, B-Rep, Windows, интерфейс, производительность на больших сценах).
4. **Допущения и риски** — что вы приняли по умолчанию, что может сломаться, на что смотреть.
5. **Что осталось** — найденные по пути проблемы вне задачи (списком, без самовольного исправления).

Нельзя: писать «всё работает» без запуска; приводить числа, которых вы не получили; выдавать расчёт или чтение кода за измерение.

## 9. Чего агент делать не должен

- Менять формат файла проекта без миграции и теста (4.5).
- Выполнять `git push --force`, переписывать историю, удалять ветки и теги, менять CI-ветку защиты без явной просьбы.
- Удалять пользовательские данные (каталог данных, база каталога, автосохранения) и менять их расположение без просьбы.
- Запускать сетевые вызовы и скачивать зависимости, не описанные в `requirements*.txt`.
- Добавлять телеметрию, отправку данных, скрытые обновления.
- Коммитить секреты, абсолютные пути своей машины, кэши (`__pycache__`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`), архивы сборки. Архив с исходниками собирается через `scripts/pack_src.sh`.
- Менять этот файл по своей инициативе. Предложите правку в отчёте, решение принимает владелец проекта.

## 10. UI: не изобретать дизайн

NestCraft — Qt-приложение со своей темой. Визуальный язык уже задан. Агент **не придумывает** новый стиль, цвета, отступы, «современный Material/Fluent/macOS-look».

### Источник правды
- Все цвета, фоны, границы, кнопки, табы, инпуты — в **`ui/theme.py`** (`ThemeColors`, `build_stylesheet`, `apply_theme`).
- Тема: светлая / тёмная в духе VS Code, следует схеме ОС.
- Локальный `setStyleSheet` — только в крайнем случае и **только** через `current_theme()`.

```python
from ui.theme import current_theme
c = current_theme()
# c.bg, c.bg_alt, c.bg_panel, c.bg_input, c.border
# c.text, c.text_dim, c.text_title
# c.accent, c.accent_hover, c.select_bg, c.select_fg
# c.error, c.warning, c.success, c.heading
```

### Запрещено
- Хардкод цветов (`#333`, `gray`, `rgb(...)`), кроме уже существующего legacy.
- Новые цветовые схемы, градиенты, тени, glassmorphism, отдельные QSS «для красоты».
- Кастомные кнопки вместо `QDialogButtonBox`, floating action buttons, bottom sheets.
- Внешние наборы иконок (Font Awesome, Material Icons и т.п.).
- Смена системного шрифта Qt на Inter/Roboto и т.п.
- Виджеты, которые работают только в light или только в dark.

### Паттерн диалога (копировать)
- `QVBoxLayout` + `QFormLayout` + `QDialogButtonBox`.
- Заголовок и подписи — **по-русски**, единицы в подписях («мм» и т.д.).
- Ширина: ориентир на соседние диалоги (обычно 380–440).
- Подсказки: `color: {c.text_dim}; font-size: 11px`.
- Числа с формулами — `SmartDoubleSpinBox` из `ui/dialogs.py`.

Перед новым UI-кодом откройте ближайший аналог в `ui/` или `ui/panels/` и повторите структуру. Иконки — только из `ui/icons/` (и `ui/icons/fasteners/`).

### Чеклист перед сдачей UI
- [ ] Нет новых hardcoded hex/rgb.
- [ ] Цвета из `current_theme()`.
- [ ] Диалог: `QFormLayout` + `QDialogButtonBox`.
- [ ] Строки на русском.
- [ ] Выглядит как соседние окна NestCraft, а не как чужой продукт.
- [ ] Корректно в light и dark.
